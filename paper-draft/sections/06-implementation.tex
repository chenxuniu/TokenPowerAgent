\section{Reference Implementation}

\subsection{Scenario and Evidence Interfaces}

The prototype accepts a versioned JSON or YAML scenario containing model,
workload, hardware, objectives, SLO, candidate space, available levels, level
costs, and verification budget.  The compiler expands knob lists into immutable
candidates and attaches resource requirements before search.  Each evidence
record stores scenario/candidate hashes, realized token histograms, software
versions, topology, phase timestamps, power streams, latency/goodput, evidence
level, status, and raw-data checksum.  Existing \bench{}\ records are imported
read-only; new jobs use the same configuration vocabulary.

\subsection{Implemented Evidence Path}

The L1 path uses a persistent, digest-pinned vLLM server and a read-only client
on an internal Docker network.  It disables prefix caching, fixes temperature
at zero, and ignores EOS.  A two-FIFO \texttt{READY/GO/DONE/ACK} handshake
places host-side reads of DCGM's cumulative device-energy counter around the
main benchmark interval, excluding loading, health checks, warmups, and result
formatting.  The calibration builder aggregates compatible L1 repeats by their
median and records dispersion and the source SHA-256.  The L0 sandbox retains
uncertainty and interpolation/extrapolation labels; the freeze and validation
tools reject modified or late predictions, mismatched repeats, and split
leakage.

\subsection{Component Architecture and Status}

Five typed boundaries expose the \textbf{scenario compiler}, \textbf{history
retrieval}, \textbf{Energy Twin}, \textbf{executor}, and
\textbf{planner/policy}.  Replay, topology prediction, L1 execution, evidence
freezing, blind validation, and Slurm rendering are implemented.  Live
scheduler monitoring, \bench{} ingestion, nested-posterior \ipig{}, and the
production LLM planner remain for the L2--L4 study; the current rule-based
planner and acquisition proxy are baselines, not relabeled final mechanisms.

All executors implement \texttt{execute(candidate, level, seed)}.  Replay
returns hidden sweep rows and costs, the serving sandbox performs L1 trials,
and the current cluster backend renders resource-bounded templates.  Live
cluster completion will return the same evidence object, leaving the planner,
guard, policy, and belief update backend-independent.

\subsection{Closed-Loop Search}

Algorithm~\ref{alg:search} specifies the target loop; the pilot currently stops
after compile, L1 calibration, L0 prediction, freeze, and validation.  The full
loop reserves top-$k$ L4 verification cost, then jointly chooses an L0--L3
candidate--fidelity action whose uncertainty can change feasibility or
dominance.  Failed jobs consume budget and update the evidence state rather
than disappearing from analysis.

\begin{algorithm}[t]
\caption{Agentic multi-fidelity Pareto search}
\label{alg:search}
\footnotesize
\begin{algorithmic}[1]
\REQUIRE scenario $S$, history $\mathcal D_0$, budget $B_m$, verify count $k$
\STATE $\mathcal X\gets\textsc{CompileAndValidate}(S)$
\STATE $\mathcal D\gets\mathcal D_0$
\STATE $\mathcal T\gets\textsc{FitTwin}(\mathcal D_0,S)$
\STATE $(B_s,B_v)\gets\textsc{ReserveVerification}(B_m,S,k)$
\WHILE{$B_s>0$}
  \STATE $g_t\gets\textsc{SemanticPlan}(S,\mathcal T,\mathcal D,B_s)$
  \STATE $\mathcal A_s\gets\textsc{Guard}(g_t,\mathcal X,B_s)$
  \STATE $(x^*,\ell^*)\gets\arg\max_{(x,\ell)\in\mathcal A_s}
  \alpha_t((x,\ell)\mid S)$
  \IF{$\Pr(\text{frontier change})<\tau_A$}
    \STATE \textbf{break}
  \ENDIF
  \STATE $y\gets\textsc{AcquireEvidence}(x^*,\ell^*)$
  \STATE $\mathcal D\gets\mathcal D\cup\{y\}$; $B_s\gets B_s-c(x^*,\ell^*)$
  \STATE $\mathcal T\gets\textsc{UpdateTwin}(\mathcal T,y)$
\ENDWHILE
\STATE $(\hat{\mathbf f},\mathbf U)\gets\textsc{Predict}(\mathcal T,\mathcal X)$
\STATE $\hat{\mathcal P}\gets\textsc{ProbabilisticPareto}(\hat{\mathbf f},\mathbf U)$
\STATE $\mathcal P_v\gets\textsc{VerifyTopK}(\hat{\mathcal P},S,k,B_v)$
\STATE \textbf{return} $\mathcal P_v$, provenance, and runnable scripts
\end{algorithmic}
\end{algorithm}

\subsection{Multi-Node Execution and Failure Handling}

The planned L2 jobs reserve a full node so topology is stable.  L3/L4 jobs will
record rank-to-
GPU placement, link/fabric counters where available, NCCL collective timing,
node power, and synchronization gaps.  The executor distinguishes application
failure, scheduler preemption, out-of-memory, telemetry loss, and SLO failure.
Recoverable failures can be retried from a deterministic template; configuration
changes create a new hash and a new evidence record.  Before L3/L4 submission,
the completed agent will present expected GPU-hours, information target, and
stopping rule for human approval.
