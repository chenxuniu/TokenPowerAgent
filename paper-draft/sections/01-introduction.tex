\section{Introduction}

An operator deploying an LLM service must choose more than a GPU.  Batch and
token limits, chunked prefill, precision, tensor and pipeline parallelism,
placement, and power policy jointly determine throughput, time to first token
(TTFT), time per output token (TPOT), and energy.  Their effects also change
with request geometry: long prompts emphasize prefill compute, long responses
emphasize memory-intensive decode, and distributed models add collectives,
pipeline bubbles, and idle synchronization.  Consequently, two configurations
with similar throughput can differ materially in joules per token or in their
ability to satisfy a tail-latency service-level objective (SLO).

The measurement path is increasingly mature.  Prior studies quantify LLM
inference energy across models, engines, and multi-GPU systems
\cite{samsi2023words,niu2025engines,fernandez2025energy}.  \bench{} further
provides declarative, phase-aligned GPU, node, and system telemetry from a
single GPU to multi-node deployments \cite{niu2026tokenpowerbench}.  Such tools
answer \emph{what did this run consume?}  They do not answer the planning
question that dominates a new deployment: \emph{given a finite allocation,
which measurements should be run before selecting a configuration?}

That question is expensive because the search space and the cost of observing
it grow together.  A single-GPU probe may reveal prefill, decode, and power-cap
behavior, but it cannot expose unseen NVLink/NVSwitch contention, inter-node
fabric behavior, placement, or queueing.  Conversely, measuring every
configuration at target scale spends the most expensive evidence on candidates
that a cheap replay or probe could have eliminated.  The useful object is
therefore neither a universal simulator nor a dense benchmark sweep.  It is a
policy for deciding \emph{which configuration--fidelity pair to evaluate next}
and when the remaining uncertainty warrants a target-scale run.

Recent MLSys systems make this distinction important.  BEAM jointly controls
batching and GPU frequency under SLOs, but assumes an offline energy--performance
table \cite{lee2026beam}.  BOute applies multi-objective Bayesian optimization
to routing and deployment choices, while OptiKIT uses full hardware trials to
tune serving configurations \cite{jiang2026boute,santavas2026optikit}.  Charon
and a large Meta deployment study make broad configuration search practical
through calibrated simulation and profiling \cite{yang2026charon,cho2026deployment}.
PROMPTS adds agent reasoning to distributed configuration recommendation
\cite{ding2026prompts}.  These systems optimize a configuration, a runtime
control action, or an agent proposal.  None treats the scale and cost of the
next measurement as a joint decision variable while requiring measured
target-scale evidence for every released energy--SLO recommendation.

We present \system{}, an agentic multi-fidelity Pareto search framework built on
\bench{}.  A scenario specifies a model, workload, target cluster, serving
runtime, SLOs, and a real-measurement budget in GPU-hours.  \system{} compiles a
typed feasible configuration pool and maintains a cross-fidelity belief over
energy, TTFT, TPOT, and throughput.  At each step it selects an action
$a=(x,\ell)$: a serving configuration $x$ and an evidence level $\ell$ ranging
from historical replay and simulation to single-GPU, intra-node, sparse
multi-node, and target-scale execution.  Its acquisition criterion, \emph{Intent-
Conditioned Pareto Information Gain} (\ipig{}), prioritizes the expected reduction
in uncertainty about the high-fidelity SLO-feasible Pareto set per GPU-hour.

The LLM component is deliberately bounded.  It maps natural-language intent to
a typed objective, selects an experiment subgoal, interprets failures, and
produces an evidence-grounded explanation.  Deterministic tools compile
feasible configurations, calculate acquisition scores, account for cost,
ingest telemetry, and compute Pareto sets.  Predictions retain fidelity and
provenance labels, and an independent gate rejects any deployment
recommendation lacking target-scale measurement.  Thus, the agent reasons
about \emph{how to acquire evidence}; it never estimates joules through
free-form language generation.

The current prototype exercises this contract end to end on one H100: it builds
an L0 profile from repeated L1 measurements, hashes a workload-transfer
prediction before holdout execution, and validates identity, ordering, error,
and interval containment.  This first experiment tests the evidence path, not
the quality of multi-fidelity Pareto search.

This paper makes four contributions:
\begin{itemize}
    \item We formulate energy-aware LLM inference tuning as \emph{budgeted
    configuration--fidelity co-selection}: recover an SLO-feasible
    energy--performance Pareto set while minimizing the real GPU-hours spent
    acquiring and verifying evidence.
    \item We design a cross-fidelity evidence model that separates phase-local
    compute from intra- and inter-node effects, preserves uncertainty under
    hardware and scale shifts, and exposes an explicit L0--L4 evidence
    contract rather than presenting simulation as cluster truth.
    \item We introduce \ipig{}, an intent-conditioned acquisition policy, and
    integrate it with a bounded LLM planner, typed executors, failure handling,
    provenance, and mandatory target-scale verification.
    \item We implement a provenance-preserving L0/L1 serving path and report a
    protocol-frozen blind H100 pilot with \PilotMeanMAPE{} four-metric MAPE and
    \PilotCoverage{} diagnostic interval containment.  We further define the
    H100/H200/B200 evaluation needed to test Pareto quality per GPU-hour,
    transfer, target-scale benefit, and the independent value of semantic
    planning.
\end{itemize}
